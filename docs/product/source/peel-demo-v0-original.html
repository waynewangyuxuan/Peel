Product thesis

Codex owns the conversation.
We make its branches visible.

这个产品不是另一个 Codex Client，也不是通用 Canvas。它只接管一个非常具体的时刻：当线性 Chat 开始产生多条值得独立探索的路径时，让这些路径继续以可见、可返回、可执行的结构存在。

Project 是工作发生的地方；Space 是一个问题展开的形状。 普通 Chat 继续留在 Codex。只有值得 Fork 的探索，才被用户主动注册进 Space。

Project → Space 是一对多

Project 长期存在、边界较大；Space 围绕一个具体问题形成。把两者合并，会把所有普通 Chat 强行拖进空间图。

五个对象，只有两个进入主图

Thread 与 Fork Edge 是空间结构；Project、Worktree 和 Subagent 提供上下文，但不应该制造第二套图。

Project

长期共享的代码与上下文边界。

Why：沿用 Codex 已有对象，不重新发明 Project。

Space

用户主动策展、围绕一个问题形成的 Fork Workspace。

Why：不是每一条普通 Chat 都值得进入空间。

Thread

真实、可继续执行的 Codex Chat。

Why：空间对象必须拥有真实历史，而不是复制出来的卡片。

Fork Edge

Parent、Child 与准确 Fork Turn。

Why：Edge 只表达 Conversation lineage，不表达任意依赖。

Worktree

某条 Thread 当前运行的代码环境。

Why：只作为名字、Diff 等 metadata，不做 Execution Dashboard。

Subagent

Parent Thread 内部的后台工作。

Why：折叠在 Activity 和 Overview indicator 中，避免变成 AgentMap。

Source of truth

产品成立的前提，是我们不再实现一套 Conversation backend。空间层必须保持薄。

Codex owns

  • Project
  • Thread history
  • Turn / Item
  • Thread name
  • Runtime status
  • Approval
  • Worktree / cwd
  • Git state

Spatial owns

  • Space
  • Membership
  • Fork position
  • Camera state
  • Collapsed subtrees
  • Last viewed state
  • Local fork draft
  • Scroll / draft

为什么不是另外三种产品

边界不是为了保守，而是为了保护真正有差异化的 Chat → Fork → Space 体验。

01

不是 Codex replacement

普通交互仍然可以发生在 Codex。我们让用户搜索和注册已有 Chat，并始终保留 Open in Codex。

02

不是 Graph editor

用户不能任意画 Edge。完整 Chat 不缩放在节点里。Graph underneath, Chat on top。

03

不是 execution dashboard

Worktree、Diff、Subagent 都是 Thread 的附加证据，不成为新的一级导航体系。

当一个问题开始分叉，把它带进 Space；当用户进入某条路径，让界面重新变回一流的 Chat。

产品的深度来自 Codex Thread 可以真实执行，但 V0 的结构只围绕 Thread Fork 建立。

UX foundation

Focus 让用户继续工作。
Overview 让用户看清工作如何分叉。

两种状态不是 Chat 页面和 Graph 页面，而是同一批 Thread 在不同观察尺度下的两套信息契约。近距离保护阅读与输入；拉远后提高识别密度。

Focus 与 Overview

Overview 不是把左侧 Tree 放大。它在 Transcript 退场后，使用额外空间展示更多确定性信息。

Focus

work state
“我现在在哪里？下一条相关路径在哪里？”
Main surface一个 full-fidelity Chat，保持 Codex / ChatGPT 的阅读、Composer、Streaming 与 Approval 体验。
Fork tree常驻但克制：Title、层级、当前节点、必要状态、轻量 Worktree / Diff 提示。
Information低密度。隐藏 Summary、Latest Result 等解释性内容，保护当前工作。
Why用户绝大部分时间是在 Chat 中工作，不是在管理一张图。

Overview

recognition state
“整个探索是什么形状？每条路径最近做了什么？”
Main surface没有 Focus Chat，没有 Composer；完整 Fork Tree 成为主界面。
CardsTitle、Branched from、Fork snippet、Latest user、Latest result、Status、Worktree、Diff、Subagents。
Information高密度但确定性。所有重要 Snippet 都能回到真实 Turn。
WhyTranscript 不可见后，用户需要更多信息来识别节点，而不是依赖 AI 猜测。

Hero flow：Branch from here

空间能力从熟悉的 Chat 行为中长出来。Peel 是关系生成的动作；Focus 是关系生成后的稳定工作状态。

01 · Existing chat

Search & open

先以普通 Chat 读取已有 Codex Thread。阅读本身不自动注册进 Space。

02 · Exact turn

Branch from here

从一个 Completed Turn 创建 Branch。也可以使用 Peel handle 作为高带宽快捷方式。

03 · Local preview

Fork Draft

Composer 立即获得焦点；可选择 Current workspace / New worktree；Escape 可取消。

04 · Durable change

First-send commit

第一次 Send 才创建真实 Codex Fork 与可选 Worktree。失败不丢 Prompt。

05 · Stable shell

Focus / Overview

Child 成为真实 Thread；Tree 更新；用户可以继续工作或 Zoom out 理解全局。

六条 UX 底层原则

后续增加 Diff、Convergence 或 GitHub 时，这些原则拥有更高否决权，防止产品逐渐变形。

Chat first, Space second

普通状态先像一个好的 Chat。 空间结构只在 Fork 和 Overview 时成为主视觉。

Graph underneath, Chat on top

完整 Chat 永远在 screen space。 不把长 Transcript 和 Composer 缩放进 Canvas node。

Deterministic before interpretive

先展示可验证事实。 V0 不让模型擅自宣布 Decision、Conclusion 或 Open Question。

Stable spatial memory

新增 Child 不重排旧节点。 Overview 位置可拖动、可持久化，自动整理必须显式触发。

Execution is metadata

Worktree 是标签，Diff 是证据。 Canvas 的 Edge 永远只表达 Chat Fork。

Familiar first, Peel second

Branch from here 是标准入口。 Peel 拖拽提供更直接的空间感，但不能成为唯一学习成本。

V0 scope

Start off correctly 的意思不是从一开始做得多，而是先把最难逆转的信息架构与交互语义做对。

V0 must feel complete

  • Project → multiple Spaces
  • Search / register existing Codex Chat
  • Focus Tree + full-fidelity Chat
  • Branch from exact Turn
  • Peel transition + Fork Draft
  • First-send commit
  • Current workspace / New worktree option
  • Branched from exact return
  • Deterministic Overview cards
  • Stable node positions
  • Inline rename synced to Codex
  • Voice dictation in Composer
  • Lightweight Diff and Subagent indicators

Explicitly deferred

  • Generic graph editing
  • Project / execution management dashboard
  • Git branch graph
  • All Subagents as main nodes
  • Automatic Decision / Open Question inference
  • Compare → Select → Integrate
  • Convergence checkpoint
  • GitHub Issue / PR workflow
  • Replacing every Codex interaction
Focus protects the quality of the present conversation. Overview protects the memory of the whole exploration.

如果后续能力破坏其中任何一条，它就不应该进入主界面。
